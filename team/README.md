# 틈의 작은 제품팀

출퇴근길 3분을 읽기·목표 확인·놀이·경험 나누기에 쓸 수 있는 모바일 웹서비스를 만든다.

## 의사결정과 역할
사용자는 대표이자 최종 제품 방향의 결정자다. Codex는 총괄 역할로 요구를 정리하고 필요한 역할을 수행하며 결과와 한계를 보고한다. 기본 운영은 한 에이전트의 역할 전환이다. 여러 AI 담당자의 실제 분담은 사용자가 요청할 때 시작하며 상시 실행되는 조직은 아니다.

| 파트 | 핵심 질문 | 산출물 |
|---|---|---|
| 총괄 / PM | 이번에 무엇을, 왜 만들까? | 범위·우선순위·담당 조정·결과 보고 |
| 기획 | 누구의 어떤 문제를 해결할까? | 사용자 흐름·수용 기준·성공 가설 |
| 디자인 | 휴대폰에서 이해하고 편하게 쓸 수 있나? | 화면 구조·상태·접근성 기준 |
| 개발 | 현재 환경에서 안정적으로 구현할 수 있나? | 코드·저장 구조·오류 처리 |
| 품질 / QA | 실제로 작동하며 기존 기능을 유지하나? | 시나리오별 결과·결함·검증 한계 |
| 콘텐츠 / 운영 | 매일 볼 이유가 있고 출처가 명확한가? | 수집 품질·문구·운영 상태 점검 |

역할별 세부 기준은 [ROLES.md](ROLES.md), 업무 흐름은 [WORKFLOW.md](WORKFLOW.md)를 참고한다.

## 현재 제품 상태
- 기본 놀이터: 오늘의 퍼즐 바로 시작·마지막 판 이어하기·선택극·짧은 발견.
- 퍼즐: 수집/얼음 목표가 있는 6×6 스테이지 5개, 번개·폭발 조각, 날짜별 같은 문제, 결과 공유.
- 이야기: 창작 1화, 선택 두 번·결말 네 개 수집.
- 메뉴는 놀이터·퍼즐·이야기·더보기다. 아래의 기존 기능은 홈/더보기에서 접근한다.
- 읽다: 직접 쓴 FIRE 카드와 외부 FIRE/NASA RSS 제목·원문 링크.
- 쌓다: 순자산·저축액·생활비·인출률 기반 단순 목표 계산. 브라우저 저장.
- 쉬다: 7×7 3매치, 20회 이동, 연쇄·힌트·최고 기록. 브라우저 저장.
- 나누다: 글·검색·댓글·삭제. 같은 브라우저에서만 보이는 체험 게시판.
- GitHub Pages의 정적 프로토타입이며 실제 로그인·공유 DB·수익화·행동 분석은 없다.

## 개선 방향
1. 모바일 사용성과 오류 처리를 먼저 다듬는다.
2. 읽기와 자산 확인 중 무엇이 재방문을 만드는지 사용자 체험으로 확인한다.
3. 실제 커뮤니티 수요가 확인되면 인증·DB·신고·운영 기능을 함께 설계한다.
4. 상업 운영 전에 호스팅·개인정보·데이터 보존 방식을 결정한다.

기획 중인 개선은 [BACKLOG.md](BACKLOG.md), 결정 기록은 [DECISIONS.md](DECISIONS.md)에 남긴다. 업무 시작은 [briefs/TEMPLATE.md](briefs/TEMPLATE.md)를 필요한 만큼 작성하는 것으로 충분하다.
