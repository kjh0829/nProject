# 알찬끼의 작은 제품팀

적은 돈으로 알차게 먹고, FIRE 목표와 월 예산 생활을 내 속도로 그려보는 모바일 웹서비스를 만든다.

## 현재 사용 흐름
| 메뉴 | 하는 일 |
|---|---|
| 홈 | 세 핵심 도구 진입, 내 진행 요약, 한끼 예시 구경 |
| 한끼 | 예산·끼니 수·재고로 포장 구매 조합 비교, 구매·조리 후 재고 관리 |
| 목표 | 자산·월 투자·월 생활비로 FIRE 계산, 선택형 티커 도구 |
| 월예산 | 항목 ON/OFF 생활비 배분, 가상 한 달과 개인 기록 |
| 기록 | 내 식탁·레시피 작성·저장한 계획·생활 기록·쉬는 틈·보관함 |

예전 읽기/퀴즈/한 줄 일기, 7×7 자유 매치, 개인 게시판 체험은 보관함에서 계속 사용할 수 있다. 기존 주소와 데이터는 유지한다. [전체 재검토와 구현·검증 기록](briefs/SITE-REVIEW.md).

## 현재 제약
- GitHub Pages 학습용 정적 프로토타입이다. 개인 기록은 이 브라우저에만 보관하며 계정·기기 간 동기화·공유 DB는 없다.
- 식사 예시 4개는 가정 단가와 AI 이미지다. 실제 사용자 글/시세로 표현하지 않는다. 사진 포함 개인 레시피는 별도로 저장한다.
- 식사 일지 CSV는 사진·레시피·FIRE 계획 전체 백업이 아니다. 브라우저 데이터 삭제 영향은 기록 탭에서 안내한다.
- FIRE 수익률과 생활비 비율은 가정/예시다. 수익이나 실제 주거 가능성을 보장하지 않는다. 주가 조회는 공개 중계 서비스에 의존하며 평가액·생활비를 외부로 보내지 않는다.
- 행동 분석·실제 트래픽/수익 측정은 도입하지 않았다. 재미와 재방문은 실사용으로 확인할 가설이다.

## 다음 우선순위
1. 실제 식사 3~5개로 입력/원가 기준 검증 후 레시피 다양성 확대.
2. 전체 개인 기록의 백업·복원.
3. 일주일 실사용으로 반복 방문 이유와 불편 확인.
4. 기존 코드 분리, 데이터 수집 안정화, 상업 운영 전 호스팅 검토.

## 운영 방식
사용자는 제품 방향의 결정자다. 기본적으로 한 에이전트가 기획·디자인·개발·QA 역할을 차례로 수행한다. 여러 담당자의 병렬 작업은 사용자가 요청할 때 시작하며 상시 직원 조직은 아니다. 책임은 [ROLES.md](ROLES.md), 절차는 [WORKFLOW.md](WORKFLOW.md), 과제는 [BACKLOG.md](BACKLOG.md)를 따른다.
