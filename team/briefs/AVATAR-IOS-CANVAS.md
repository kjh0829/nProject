# iPhone 반복 종료 대응: Canvas 렌더링

## 관찰과 이전 수정의 한계

사용자 화면은 iOS 브라우저가 페이지를 반복 종료한 화면이다. 이전의 캐시 혼합 TypeError 수정과 예외 경계는 네이티브 렌더러 종료를 막지 못했다. OS 진단 로그가 없으므로 메모리/GPU 종료 원인을 확정했다고 표현하지 않는다. 기존 기본 캐릭터 하나에는 SVG 요소 610개, `<use>` 129개와 필터 4개가 있었고 상점은 여러 캐릭터를 함께 그렸다.

## 제품 렌더링

- `avatar-canvas.mjs`가 원본 PNG를 Canvas 2D로 합성한다. 제품의 홈·옷장·보상·코디 카드에는 SVG 메시/필터/재귀 참조를 넣지 않는다. 정지 원화의 품질·아이템 ID/가격·지갑·구매·진행 저장은 유지한다.
- 목/손목/허리 삼각망은 SVG 검사 렌더러와 같은 좌표와 함수를 사용한다. 새 의상의 피팅 등록과 필수 필드 검사는 완화하지 않는다. 목/손목 가림, 부츠 깊이, 안경/가방/머리의 앞뒤 순서도 Canvas에 적용한다.
- 일반 미리보기는 최대 560×1312, 확대는 656×1536, 썸네일은 420×420 경계 안에 그린다. 각 작업의 임시 표면은 종료 시 0×0으로 해제하고 작업은 하나씩 실행한다.
- 원화 캐시는 1,600만 픽셀 예산으로 관리하며 사용 중인 비트맵은 보존하고 오래된 비트맵을 닫는다. 이 수치는 자체 관리 픽셀 예산이며 브라우저 프로세스의 실제 RSS 측정값이 아니다.
- 화면을 떠나거나 백그라운드/페이지 캐시에 들어가면 표시 버퍼를 0×0으로 만들고 진행 중인 숨은 미리보기를 취소한다. 다시 표시할 때만 그린다. `#read` 직접 진입에는 캐릭터 렌더러/원화가 필요하지 않다.
- PNG 코디 카드는 동일한 Canvas 결과를 사용한다. SVG를 다시 디코딩하는 경로를 제거한다. 준비되지 않은 그림으로 구매/착장 변경을 하지 않는다.

## 검사

- `avatar-runtime-browser.cjs`: Chromium/WebKit 각각 360/390px·DPR3, 52개 의상, 12개 피부/표정, 반복 탭 이동, pagehide/pageshow, 버퍼 해제, PNG, 기존 저장 보존을 검사한다. `.github/workflows/avatar-runtime-check.yml`에서 두 엔진을 필수 실행한다. Linux WebKit은 실제 iPhone 기기 검증과 구분한다.
- master 배포에서는 HTML/렌더러 파일의 해시가 해당 커밋과 일치할 때까지 기다리고, 두 엔진으로 공개 Pages 주소의 동일한 동작을 다시 검사한다.
- `avatar-catalog-browser.cjs`: 동일한 776개 사례를 SVG와 Canvas 모두 검사한다. 실제 원화에 추가한 허리 표식도 두 렌더러에서 추적하며, 전체 13개 분할과 누락 집계를 확인한다.
- 구매/보상·코디 프리셋·게임·확대·원화 참고·내보내기 검사를 유지한다. `avatar-art.mjs`는 개발용 원화 검사에만 직접 사용한다.
