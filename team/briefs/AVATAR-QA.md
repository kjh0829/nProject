# 확장 가능한 의상 검사 규격

## 목표와 보장 범위
새 옷이 늘어날 때 검사 목록을 손으로 수정하지 않아도 등록된 모든 아이템과 서로 맞닿는 부위의 조합을 검사한다. 기존 결함 회귀와 확대 육안 검토를 함께 유지한다. 자동 검사는 알려진 접합/등록 규칙을 검사하며 그림의 자연스러움, 모든 픽셀, 모든 6부위 전체 조합의 무결함을 보장하지 않는다.

## 파일과 역할
- `docs/avatar-data.mjs`: 공개 아이템 ID/가격/부위. 기존 ID·가격·무료 기본품·지갑 형식은 유지한다.
- `docs/avatar-layers.mjs`: atlas 크기, 원본 source/target 사각형, 각 아이템의 **필수 profile**, 필요한 분할 텍스처 segments. PNG 원본은 편집하지 않는다. 다른 크기의 새 atlas도 registry에 등록할 수 있다.
- `docs/avatar-profiles.mjs`: 몸체와 자세에 맞춘 렌더링 규칙. 짧은/긴 소매, 코트 앞트임, 바지 길이, 멜빵 겹침, 부츠, 안경·가방 등의 의미를 정의한다. renderer에서 개별 아이템 ID로 분기하지 않는다. 새 실루엣에 기존 profile을 무조건 재사용하지 말고 해당 몸체에 맞는 규칙/검사를 명시한다.
- `docs/avatar-qa.mjs`: 등록 검사, 카탈로그 기반 사례 생성, 분할, 결과 누락/중복/커밋 검증. 조합은 아이템 개수에서 계산하고 특정 아이템명 배열을 검사 대상 목록으로 사용하지 않는다.
- `docs/avatar-qa-render.mjs`: 실제 SVG/PNG 합성 결과의 픽셀을 읽어 허리·소매/손·발목 연결, 머리/얼굴 가림, 부위별 기준점/빈 원화, 멜빵/부츠 순서를 검사한다. PNG 자산을 수정하거나 개인 저장소를 읽지 않는다.
- `tests/avatar-fit-browser.cjs`: 이미 발생했던 흰 천/검은 조각, 니트 허리 틈, 라일락 두피, 달빛 머리, 멜빵/부츠의 구체적 회귀 사례. 일반화된 검사로 대체해 삭제하지 않는다.
- `docs/avatar-review/`: 지갑과 분리된 개발용 확대 검토실. 전체 목록/아이템/검사 그룹/페이지/사례 링크, 좌표 가이드와 현재 페이지 픽셀 검사를 제공한다. 게임 사용자의 실제 착장을 표시하지 않는다.

## 자동 생성하는 범위
1. 모든 아이템 단독 원화: 등록 부위, 실제 이미지가 비어 있지 않은지, profile의 고정 몸체 기준점을 확인.
2. 상의 × 하의: 허리와 소매, 멜빵 앞뒤 순서.
3. 하의 × 신발: 발목과 부츠 앞면, 긴 바짓단 처리.
4. 머리 × 모자 없음/전체 모자 × 전체 표정.
5. 머리 × 소품, 상의 × 소품.
6. 피부 × 표정, 머리 × 피부.

같은 전체 착장/피부/표정은 중복 제거하되 해당 검토 그룹은 보존한다. 현재 52개 아이템은 **776개 실제 실행 사례**다. 그룹의 원래 교차 수 합계와 중복 제거 실행 수는 다르다. 새 아이템을 하나 추가하면 각 관련 조합에 자동 포함된다. 해당 동작은 가상 새 아이템을 추가하는 단위 검사로 확인한다.

## 등록 시 필수 검사
- 카탈로그 중복 ID, artwork 누락/고아 항목, 알 수 없거나 부위가 다른 profile은 오류.
- source는 등록된 atlas 안의 유효한 양수 사각형, target은 현재 전신 프레임 안의 유한 좌표여야 한다. 음수 폭/NaN/프레임 밖은 오류.
- 분할 신발/안경은 정해진 source/target 세그먼트를 모두 등록한다. waist profile은 정상적인 연결 위치와 겹침 폭이 필요하다.
- atlas 파일이 실제 존재하고 크기와 RGBA PNG 형식이 registry와 일치해야 한다. 검사한 원본 파일의 SHA-256·바이트 크기를 CI 증거에 남긴다.
- 새 몸체·포즈·프레임으로 바꾸려면 규격 버전과 기준점/검사를 함께 변경한다. 새 옷 한 벌 때문에 전역 기준을 느슨하게 풀지 않는다.

## 새 의상 추가 절차
1. 같은 고정 몸체·자세에 맞춘 투명 원화를 제작하고 새 atlas를 등록한다. 기존 생성 원본은 보존한다.
2. catalog와 layer에 새 ID/가격/부위, `atlas/source/target/profile`을 함께 등록한다. 기존 적합한 profile은 재사용하고, 새로운 실루엣이면 profile과 물리적 검사도 추가한다.
3. 아래 명령으로 등록·접합·기존 게임 재화 회귀 검사를 수행한다. 누락/불완전 등록을 우회하기 위해 검사 목록에서 아이템을 빼지 않는다.
4. 담당자가 검토실에서 새 아이템을 선택해 해당 조합을 **확대 육안 검토**한다. 얼굴·목·팔꿈치·손목·허리·양쪽 발목·모자/머리·소품을 본다. 이 작업은 자동 초록 표시만으로 대체하지 않는다. 별도 사용자 승인 절차를 요구하는 규칙은 아니다.
5. CI 결과 JSON과 확대 시트를 보고 실패한 `case ID / rule / point`를 재현한다. 수정한 다음 관련 사례와 이전 결함 회귀를 재실행한다.

```sh
node tests/avatar-qa.test.mjs
node scripts/check-avatar-assets.mjs
node tests/avatar.test.mjs
node tests/avatar-cel.test.mjs
python3 -m http.server 8000 --directory docs
# 별도 터미널, Playwright 설치 후 실행
node tests/avatar-catalog-browser.cjs
node tests/avatar-review-browser.cjs
node tests/avatar-fit-browser.cjs
```

로컬 시스템 Chromium은 `CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium`으로 지정할 수 있다. 전체 계획 대신 특정 CI 조각은 `AVATAR_QA_SHARD=0`처럼 실행한다. 부분 실행 성공을 전체 검증으로 표현하지 않는다. `scripts/summarize-avatar-qa.mjs`는 모든 분할 결과가 있어야 통과한다.

## CI와 성장 비용
`.github/workflows/avatar-art-check.yml`이 관련 push/PR/수동 실행에서 등록 검사 → 조합 렌더링 → 완전성 집계를 실행한다. 한 분할은 최대 64사례, 최대 동시 실행 3개다. 현재는 13분할이며 아이템 증가에 맞춰 분할 수를 자동 계산한다. 기본 안전 예산은 최대 16분할이다. 초과하면 명시적 오류로 중단하고 예산/작업 구성을 검토한다. 임의 표본 추출이나 조용한 사례 누락으로 통과시키지 않는다.

각 분할이 실패해도 나머지 분할을 계속 검사하고 결과/확대 PNG 시트를 artifact에 보존한다. 집계는 전체 계획 대비 사례 ID가 정확히 한 번씩 실행됐는지, 실패가 없는지, 버전/커밋/실행 수/분할 수가 맞는지 확인한다. `wardrobe-summary` artifact의 HTML/JSON에 성공·실패·누락을 표시한다. 검토실 링크는 최신 사이트이므로 과거 결과는 해당 커밋/asset 해시와 artifact 이미지로 확인한다.

**현재 Pages 배포는 별도 GitHub Pages 워크플로이므로 이 검사 실패만으로 공개 배포가 자동 차단되지는 않는다.** 검사가 통과했다고 Pages 성공으로 표현하거나 그 반대로 표현하지 않는다. 새 의상 릴리스는 검사와 확대 검토를 마친 상태로 진행한다. 실제 병합/배포 강제 차단에는 저장소의 required checks/Pages 설정을 별도로 연결해야 한다. 이 작업에서 저장소 관리 설정을 변경했다고 주장하지 않는다.

## 확인한 실패 감지
단위 검사에서 등록/프로필/좌표/세그먼트 오류, 새 아이템 누락, 분할 누락·중복·다른 커밋·실패를 숨긴 통과 결과를 거부한다. 과거 달빛 머리의 잘못된 원위치는 픽셀 회귀가 실제로 실패하는 것을 확인했다. 검토실은 360/390/1200px에서 필터/가이드/실제 검사/직접 링크/페이지 이동과 개인 지갑·금융 저장 byte 보존을 검사한다.


## 상의 목선 규격 (2026-11-16)
9개 상의를 목 주변 확대 상태에서 검토했다. 평면 옷 그림의 목구멍이 공통 목보다 오른쪽에 있고 뒷깃이 피부를 덮던 문제를 수정했다. 원본 PNG는 그대로 보존한다.

- 모든 top의 `avatar-layers.mjs` 등록에는 `neckline: {shift, scale, lift, tilt, opening}`이 필수다. opening은 좌측 끝/곡선 제어점/우측 끝의 세 점으로 피부가 드러나는 범위를 정한다. 고깃·후드·라운드넥을 같은 높이로 자르지 않는다.
- `avatar-neckline.mjs`가 목 주변만 삼각형 망으로 정렬한다. 400 아래에서는 별도의 소매 보정을 적용하고 허리 중심 열은 고정한다. 접힘 방지를 위해 shift 범위와 공통 격자 포함 여부를 등록 단계에서 검사한다.
- 상의 마스크는 실제 표정 원화의 목 알파와 목구멍의 교집합만 잘라낸다. 앞쪽 옷깃은 남기며 얼굴 원화 아래쪽의 어깨 피부 돌출은 공통 해부학 클립으로 가린다. 코트 안감은 별도로 연결한다.
- 자동 사례에 모든 상의 × 피부 4 × 표정 3을 포함한다. 현재 704개 고유 사례/11분할이다. 목 피부 노출 지점의 상의 투명도, 피부 연결, 앞깃 유지, 코트 내부 연결을 실제 렌더 픽셀로 검사한다.
- 새 상의는 최소 목·깃 확대와 전신을 육안 검토해 opening/shift를 조정한다. 픽셀 통과만으로 목깃의 모양이 자연스럽다는 판정을 대신하지 않는다. 옷장 썸네일과 착장은 동일 합성기를 사용한다.


## 목·손목 연결부 재검토 (2026-11-16)
앞선 수정은 목의 몇 지점에 피부가 보이는지 확인했지만, 옷 입구의 전체 폭/깊이와 소매의 실제 끝 위치를 충분히 검증하지 못했다. 9개 상의의 목과 양쪽 손목을 나란히 확대해 검토했다.

- 목깃은 좌우 이동 외에 폭과 높이를 보정한다. 실제 얼굴 원화의 목 부분만 소폭 연장하고 242~252 좌표에서 점진적으로 합성해 수평 경계선을 없앤다. 얼굴/머리 크기는 바꾸지 않는다. 앞쪽 옷깃과 뒤쪽 입구의 역할을 구분한다.
- 긴 소매의 `cuffs: {scale, rightShift, openings, frames}` 등록이 필수다. 580 아래 소매를 실제 손목까지 줄이고 오른쪽 소매를 손목 방향으로 이동한다. 삼각형 망의 꼭짓점을 공유하므로 분리된 소매 조각 사이에 틈이 생기지 않는다. 허리 중심은 고정하고 긴 코트 끝에서는 변위를 다시 0으로 돌린다.
- 양쪽 소매 입구는 실제 몸 원화의 피부 알파와 교차해 처리한다. 손/손가락 원본은 그대로 보존한다. 손목 노출 마스크는 피부를 대각선으로 잘라내지 않도록 충분한 연결 범위를 확보한다.
- 모든 top-look/상의 단독 검사에 손목 입구의 투명도/피부 연결, 소매 원단 유지, 소매가 손바닥을 덮지 않는지를 포함한다. 옛 소매 길이를 복원한 잘못된 fixture도 회귀 검사에서 거부한다.
- 검토실에는 좌/우 손목 확대를 추가했다. 자동 검사의 초록 표시를 미적 품질의 보장으로 표현하지 않는다. 최종 확대 검토는 피부 경계선·옷깃의 남은 빈 공간·손목에 소매가 들어가는 모양을 각각 확인한다.

- 전신 검토에서 보정 망의 가는 밝은 경계선을 발견해, 꼭짓점 방향의 padding 대신 모든 변을 동일 폭으로 바깥쪽 확장하도록 수정했다. 단색 원단 fixture의 내부 알파를 검사해 이음새를 검증한다. PNG 원화는 수정하지 않는다.


## 옷별 카라·손목 각도 (2026-11-16)
같은 손목 입구와 길이 보정값을 공통 적용하던 방식에서 원화별 중심/기울기 차이가 남았다. 9개 상의의 목·손목 확대와 전신을 비교해 다음을 보정했다.

- `neckline.tilt`로 목깃의 좌우 기울기를 등록한다. 코랄·코트·벚꽃·바다·별빛·숲·카페 7종은 개별 중심/기울기를 조정하고, 반팔/후드는 기울기 0을 유지한다. 피부용 입구 곡선도 같은 방향에 맞춘다.
- 각 긴 소매는 좌우 독립 `frames`를 필수 등록한다. 실제 원화 입구의 pivot/angle, 추가 회전 turn, 입구 폭 width, 이동 shift를 갖는다. 소매 끝에서 실제 몸체 손목 방향으로 적용하고 팔꿈치/허리/코트 끝에서는 부드럽게 원래 좌표로 잇는다.
- 고정 몸 원화의 660~680행 피부 단면을 읽어, 손목 기준을 화면 왼쪽 (275,672)/23도와 오른쪽 (744,674)/-27도로 정했다. `avatarWristRig`와 등록 검사에서 입구 중심·방향 일치를 검증한다. 좌우 데이터를 바꾸거나 이동/회전을 누락하면 오류다.
- 손목 마스크는 소매 앞쪽의 완만한 곡선 아래에서 손 방향으로 열린 형태다. 소매 앞 원단은 유지하고, 그 아래로 손이 나오도록 처리한다. 입구 전체나 뒤쪽 경계를 잘라 피부 구멍/V자 절개가 생기지 않게 한다. 실제 피부 알파와의 교차, 원본 손/손가락 보존은 유지한다.
- 입구 중심만 검사하던 방식에 더해, 각 손목 앞 원단의 유지와 손이 나오는 곡선 아래 손목 축을 따라 3열 × 7개 지점에서 원단이 손을 가리지 않고 피부가 이어지는지 검사한다. 원단 보존 검사지점도 손목 법선의 위쪽 24px에 둔다. 예전 고정 좌표 (760,650)는 옷을 제대로 이동하면 더 이상 오른쪽 소매 안의 지점이 아니므로 사용하지 않는다.
- 원본 PNG·목/손 피부색·아이템 ID/가격·개인 지갑 데이터는 바꾸지 않는다. 각도 일치 자동 검사와 그림의 미적 품질 검토는 별개다.

- 가이드 없는 확대 검토에서 상부 반타원 컷이 V자처럼 보이는 문제를 발견해 앞쪽 곡선 아래만 가리도록 최종 조정했다. 원단 기준면은 불투명하고 그 아래 피부 통로는 투명해야 한다. 옛 닫힌 타원으로 앞쪽 원단을 관통해 피부 구멍을 만드는 fixture를 거부한다.


## 전신 검사 확장
[전신 피팅 검토](AVATAR-FULL-FIT.md)에 따라 legFit/부츠 입구/렌즈 기준점을 필수 등록한다. 현재 776개 고유 사례/13분할이며 안경의 모든 표정과 부츠의 모든 하의·피부 조합을 포함한다. 원단 보존과 실제 피부 영역을 분리하며, 가방의 머리 앞뒤 순서·어깨 밖 돌출·부츠 입구의 다리 연결·밑단 중심을 검사한다.

새 친구 소품의 perchPoints는 모든 상의에서 실제 접촉이 있어야 한다. 전신 검토에서 발견한 긴 소매의 뜬 발을 어깨 안쪽으로 보정하고, 이후 상의 추가 시에도 이 접점을 검사한다.

## 허리 자세 검사 v2 (2026-11-21)
현재 규격은 [상·하의 허리 피팅](AVATAR-WAIST-FIT.md)을 따른다. 모든 상·하의에는 `waist.points/rise`가 필수이며, 고정 42px 허리 늘리기는 공통 L/F/R 보정으로 대체했다. 앞선 목/손목 규격에서 “허리 중심 열 고정”은 다른 관절을 움직이지 않는 공통 허리 보정으로 확장했다. 픽셀 검사에 실제 렌더된 기준점/골반 연결과 잘못된 변환 회귀를 추가했다. 작은 화면에서는 삼각형 겹침을 늘려 외곽이 튀어나오게 하지 않고 합성 원단의 높은 알파를 보정한다. 176px 렌더에서 이 보정을 뺀 결함 fixture를 확인한다. 전체 사례 수는 776개/13분할을 유지한다.
