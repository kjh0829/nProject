# 아바타 오류와 페이지 진입 복구

## 재현된 실패

새 렌더러와 허리 등록 이전의 `avatar-layers.mjs`가 함께 로드되면 `layer.waist.rise` 접근에서 TypeError가 발생했다. 홈 캐릭터와 보상 모듈이 정적 의존하던 렌더러의 예외가 모듈 초기화까지 중단했다. 실제 기기의 전체 페이지 종료 여부와 메모리 부족은 확인하지 않았으며, 위 캐시 혼합 오류를 별도로 재현했다.

## 수정

- 허리 정보가 없는 이전 등록은 허리 변형을 생략해 호환한다. 새 의상의 필수 등록 및 catalog QA는 그대로 엄격히 검사한다.
- 제품 UI는 `avatar-runtime.mjs`를 통해 렌더러를 비동기로 불러온다. 로딩·렌더링 실패는 안내와 수동 새로고침으로 처리하며 메뉴·게임·저장 모듈을 중단시키지 않는다. 자동 새로고침이나 저장 데이터 초기화는 하지 않는다.
- 미리보기가 준비되기 전에는 의상 구매/착장 변경을 막고, PNG 내보내기는 실제 SVG를 기다린다. 실패 안내를 코디 이미지로 저장하지 않는다.
- 보이지 않는 옷장·홈·여행 캐릭터는 그리지 않고 화면을 떠나면 무거운 SVG를 해제한다. 첫 홈 진입에서 숨겨진 상점의 여러 캐릭터를 함께 만들지 않는다.
- 원단 합성 필터 영역은 전신 프레임으로 제한한다. 원본 PNG·좌표·가격·아이템 ID·지갑·진행 저장 구조는 변경하지 않는다.
- 제품 진입 모듈과 렌더 보조 파일의 복구 버전을 갱신한다. 진단 화면은 실제 렌더러를 직접 검사하여 실패를 숨기지 않는다.

## 검증

`tests/avatar-recovery-browser.cjs`는 360/390px에서 허리 정보가 없는 캐시, 렌더러 HTTP 실패, 실행 중 예외를 주입한다. 홈·꾸미기·기록·게임 이동, 보유 의상/구매 내역 보존, 실제 스테이지 완료/보상 지급, 실패 시 내보내기 차단, 가로 넘침을 확인한다. 지연 로드 중 메뉴 이동과 구매 차단, 늦게 도착한 렌더러가 숨겨진 옷장을 다시 만들지 않는지도 검사한다. CI의 기존 구매/보상·전신 피팅·776개 catalog 검사는 별도로 유지한다. GitHub Pages 배포와 실제 휴대폰 검증은 서로 다른 확인 사항이다.
