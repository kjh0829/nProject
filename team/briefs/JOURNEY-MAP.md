# 늘어나는 여행 지도를 위한 UI와 콘텐츠 구조

## 화면
- 전체 지역을 세로로 나열하던 지도를 선택한 지역 하나로 변경했다. 상단의 이어하기는 지도에서 둘러보는 위치와 무관하게 실제 진행 판으로 연결된다.
- 지역 선택(select), 이전/다음 지역, 현재 위치 바로가기. 각 지역은 최대 10판씩 구간으로 나눠 그 구간만 DOM에 만든다. 잠긴 지역은 둘러볼 수 있으나 플레이는 기존 순차 해금을 따른다.
- 작은 원형 노드와 완료 별, 현재 위치, 선택 상태를 구별한다. 노드를 고르면 아래에 목표·이동·내 최고 기록과 시작 버튼을 보여준다. 긴 지역 이야기는 접어두었다.
- 지역 ID/구간/선택한 판을 #journey?region=glass-garden&page=1&level=6에 보관해 새로고침과 뒤로가기를 지원한다. 잘못된 지역/구간은 안전한 유효 범위로 정리한다.

## 추가 방법
1. docs/journey-content/에 지역 pack 파일 추가. id/name/icon/color/intro/ending/levels를 지정한다. 스테이지에는 id/name/subtitle/color/target/moves/ice를 지정한다.
2. docs/journey-data.mjs에서 import하고 createJourneyCatalog 배열의 **끝**에 추가한다. 기존 지역 ID와 스테이지 번호/순서/규칙/seed 버전은 유지한다. 새 스테이지 ID는 마지막 번호+1부터 연속으로 지정한다. 지역당 판 수는 5로 고정하지 않는다.
3. catalog가 중복 지역·빠지거나 재정렬된 판 번호·목표/이동/색상/얼음 범위를 검사한다. 총 판 수, 별 합계, 지역 범위, 결말 판, 다음 판과 완주 판단은 실제 카탈로그에서 계산한다. HTML에 15판/지역당 5판 상수를 추가하지 않는다.
4. 새 판들의 해답·목표와 난이도를 검증한 뒤 게시한다. UI 구조가 확장 가능하다는 사실은 무작위 판의 재미/해결 가능성을 보장하지 않는다.

기존 teum-journey-v1 키와 모든 1~15번 판의 규칙·배치·저장 형식은 유지한다. 기존 마지막 판을 끝낸 사람은 새 지역 추가 시 다음 번호가 자동 해금된다. 실제 콘텐츠는 이번 변경에서 **3지역·15판 그대로**다. 새 예약이나 자동 발행 작업은 만들지 않았다.

## 검증
- journey-catalog.test: 43지역·1,495판의 합성 검증 카탈로그, 다른 지역별 판 수(37), 구간별 최대 10노드, 1,000판 이후 현재 위치와 기존 완주자의 추가 지역 해금, 기존 15판 데이터 보존, 잘못된 pack/주소 검사.
- journey-map-browser: 320/360/390/1200px 지역 선택·현재 위치·미리보기·잠금·주소 복원/뒤로가기·가로 넘침. 별도의 브라우저 요청 가로채기로 같은 1,495판 합성 데이터를 공급해 구간 이동과 최대 10개 노드 렌더링을 검증한다. 합성 1,001번 판의 실제 진입, 지역당 37판 구성의 52번 판 통과 후 지역 결말과 53번 연결도 확인한다. 합성 콘텐츠/기록은 테스트에만 존재하며 게시하지 않는다.
- 기존 journey-focus-browser는 현재 표시되는 5판만 검사하도록 수정하고 진행/undo/restart/resume/해금/집중을 그대로 검증한다. 기존 퍼즐/점수 회귀도 실행한다.

많은 지역의 메타데이터는 select에 표시하지만 게임 노드는 현재 구간만 렌더링한다. 수만 개의 콘텐츠 전체를 지연 로딩하는 서버/CDN 설계는 별도 후속 범위이며 지금의 정적 카탈로그로 그 성능을 주장하지 않는다.
