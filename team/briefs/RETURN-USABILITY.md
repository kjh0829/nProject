# 다시 열기 편한 화면과 날짜별 도전

## 검토
- 기존 showView가 화면을 바꿀 때마다 scrollTo(0)를 호출해 읽던 위치와 브라우저 뒤로 가기의 문맥을 잃었다.
- 날짜 도전은 URL로 과거 날짜를 열 수 있었지만 목록이 없어 놓친 날을 찾기 어려웠다.
- 오늘 이미 통과해도 홈의 시작 문구가 같아 개인 진행이 보이지 않았다.
- 일부 모바일 폼의 작은 글씨는 iOS 입력 자동 확대의 원인이 될 수 있고, 360px 게임 조각도 약 42px로 작았다.

## 구현
- navigation-core.mjs / navigation.mjs: 7개 화면과 쿼리별 스크롤 위치를 메모리에서 보존한다. 일반 탭 이동·브라우저 뒤로 가기·같은 탭 재선택을 구분한다. 위치는 최대 64개이며 새로고침·다른 기기 동기화는 제공하지 않는다.
- 읽을거리·계산기·게시판·게임·이야기의 기존 주소와 상태를 유지한다. 새 화면 전환은 접근성 안내로 알린다.
- 홈에 한국 날짜 기준 최근 7일 도전을 표시한다. 시작·진행·실패 후 재도전·통과 기록을 실제 브라우저 저장값으로 구분한다.
- 오늘 도전 버튼과 요약도 개인 상태에 따라 바뀐다. 없는 기록을 방문자 지표로 꾸미지 않는다.
- mobile.css: 모바일 입력창 글씨를 16px 이상으로 맞추고, 숫자 입력·기록·댓글·복사 영역에 적용한다. 핀치 확대는 유지한다.
- 360px/390px에서 새 퍼즐 조각의 간격을 조정해 터치 폭을 44px 이상 확보한다. 일반 동작 버튼 높이와 하단 안전 영역도 보완한다.
- 고정된 착시 콘텐츠의 ‘오늘’ 문구를 ‘잠깐의 발견’으로 바꿔 매일 새 콘텐츠처럼 보이지 않도록 한다.

## 검증
- tests/navigation.test.mjs: 화면·쿼리 식별, 예외 주소, 도구 메뉴 연결, 독립 스크롤·메모리 제한, 연도/윤년을 넘는 최근 7일, 개인 도전 상태와 시작 버튼 문구.
- tests/navigation-browser.cjs: 360px/390px에서 탭 위치 복원, 같은 탭 유지, 브라우저 뒤로 가기, 날짜 선택, 통과 결과 열기, 16px 입력 글씨, 44px 퍼즐 조각, 가로 넘침과 오류 확인.
- 기존 일일 기록·게시판·5개 퍼즐·되돌리기·이야기 결말 검증도 유지한다.
- iOS Safari의 실제 키보드·확대 동작은 실기기 후속 확인이 필요하다. Chromium 글씨·레이아웃 검증과 구분한다.
