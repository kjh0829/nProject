# 알찬끼 전체 재검토와 정리

## 문제와 실행 계획
기능이 추가될 때마다 링크와 설명도 누적되어, 최근의 핵심 기능인 식사·FIRE 목표·월 예산 생활을 찾기 어려웠다. 홈은 큰 식사 소개/중복 CTA에 치우쳤고 더보기는 오래된 읽기·퀴즈·정원·일기·게시판·두 게임이 섞여 있었다. 기존 기록을 지우거나 기능을 없애는 대신, 기본 노출과 보관함을 정리한다.

| 우선순위 | 발견한 문제 | 이번 처리 |
|---|---|---|
| P0 | FIRE/생활 기능이 더보기와 페이지 하단에 묻힘 | 상단/하단을 홈·한끼·목표·월예산·기록 5개로 통일 |
| P0 | 홈의 큰 소개 그림·중복 배너·예전 숨은 히어로 | compact 소개와 3개 핵심 카드로 교체, 불필요 DOM 제거 |
| P0 | 기록과 예전 콘텐츠가 섞임 | 내 식탁·레시피 작성·FIRE 계획·생활 기록·쉬는 틈을 기록 허브로 구성 |
| P0 | 예전 콘텐츠가 첫 화면을 길게 만듦 | 읽기/퀴즈/한 줄 일기와 실험 기능을 각각 접힌 보관함으로 이동 |
| P1 | 휴대폰의 긴 기준표가 가상 선택을 밀어냄 | 예산 입력 옆에 ‘이 예산으로 한 달 살기’ 이동 버튼 |
| P1 | 저장한 생활 기록이 아래에 묻힘 | 기록 허브에서 생활 일지 위치로 바로 이동 |
| P1 | 이전 기초 글이 아직 0% 단순 계산기라고 설명 | 수익률·물가를 직접 0%로 바꾸는 현재 방식으로 정정 |

## 현재 구조
- 홈: 세 핵심 진입 카드, 실제 개인 기록이 있을 때만 진행 요약, 식사 예시 탐색.
- 한끼: 내 재료·예산으로 메뉴 고르기와 세 끼 준비.
- 목표: 세 금액 간편 FIRE, 종목별 도구는 선택해서 펼침.
- 월예산: ON/OFF 가능한 생활비 기준표와 가상 한 달.
- 기록: 내 식탁/작성, 저장한 계획, 가상 생활 기록, 현대 퍼즐/이야기, 접힌 이전 콘텐츠.

saved-meals/meal-compose와 모든 예전 주소는 유지한다. 식사 기록/사진·FIRE 자산·생활 기록·게임·일기·게시판 데이터는 삭제하거나 이관하지 않는다. 홈페이지는 실제 저장 개수/진행 여부만 읽으며 자산 금액은 노출하지 않는다. 별도 방문 분석이나 서버 전송을 추가하지 않는다. 큰 설명은 해당 기능의 기준/보관함에서 확인할 수 있게 하고, 식사 예시/가정 가격/AI 이미지/브라우저 저장 제약은 필요한 위치에 남긴다.

## 다음 우선순위
1. 실제 식사 기록 3~5개로 입력 부담을 확인하고, 사용 허락/원가 기준이 있는 레시피를 늘린다. 현재 예시 4개를 실제 이용자 콘텐츠로 표현하지 않는다.
2. 사진·레시피·재무 계획을 포함한 전체 기록 백업/복원을 설계한다. 현재 식사 일지 CSV는 전체 백업이 아니다.
3. 일주일 실사용으로 자주 여는 기능과 불편을 확인한 후 다음 작업을 고른다. 분석 시스템이나 수익/트래픽 지표를 임의로 만들지 않는다.
4. 그다음 초기 로드되는 예전 코드 분리와 공개 주가 중계의 운영 대안을 다룬다. 이번 정리에서 서버·인증·호스팅은 바꾸지 않았다.
