# 혼자 쓰는 알찬끼

## 문제와 방향
이용자가 적거나 새 글이 없어도 쓸 이유를 만든다. 남은 재료로 메뉴 선택 → 다음 세 끼 준비 → 먹은 식사와 만족도 기록 → 다음 선택의 참고로 이어지는 개인 도구를 중심에 둔다. 출석 의무·가짜 사용자·인위적인 인기 지표는 넣지 않는다.

## 구현
- #meal-lab: 재료 이름, 1인분 예산, 조리시간, 저장 메뉴 조건. 미추첨 메뉴를 먼저 고르고 재료 겹침·저장·다시 먹고 싶은 기록을 참고한다. 최근 먹은 메뉴는 우선순위를 낮춘다. 같은 조건에서 후보가 하나면 다시 뽑기를 막는다.
- 예시 4개와 개인 레시피가 후보 전부다. AI 생성·영양 추천이 아니며 외부 API를 호출하지 않는다.
- 세 끼 계획: 최대 3개, 1~20인분. 같은 이름·단위·포장량·가격 기준만 재료를 합친다. 직접 입력한 사용량은 메뉴별 표시한다. 보유 재료도 원가에 포함한다. 실제 구매비·절약액과 구분한다.
- 식사 일지: 날짜·끼니·함께 먹은 인분·1인분 원가·금액 출처·만족·메모. 같은 메뉴/날짜/끼니 재등록은 갱신, 편집 충돌은 거절. 레시피 삭제 후에도 일지 제목과 금액 스냅샷을 유지한다.
- 내 식탁: 최근 7일 기록 수·메뉴 수·기록한 원가 합계, 일지 수정/삭제, 수식 실행을 막는 CSV 셀 처리. CSV는 일지만 보관하며 사진·레시피 백업은 아니다.
- 별도 localStorage 키, 최대 1,000건. 손상 데이터·저장 실패 시 덮어쓰기/성공 표시를 하지 않는다. 기존 먹어봄 표시는 날짜 없는 별도 표시로 유지한다.

## 운영과 한계
매일 편집·AI 호출·서버 없이 현재 정적 페이지에서 작동한다. 실제 사용자가 다시 오는지, 재미가 있는지는 아직 가설이다. 예시 4개는 다양성이 제한적이다. 사용 허락과 원가 기준이 확인된 메뉴를 늘리고 개인 레시피를 축적해야 한다. 실제 공개 커뮤니티와 기기 간 동기화는 후속 서버 작업이다.
