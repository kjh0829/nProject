# 틈 제품 방향 재검토

## 결론
현재는 FIRE 학습·목표 관리·일기·게임·게시판이 병렬로 놓여 있어 한 문장으로 설명할 핵심 즐거움이 약하다. 이전 개선은 재미를 검증하기 전에 습관 장치를 추가한 접근이었다. 다음 작업은 기능 확대가 아니라 ‘출퇴근길 3분 안에 자발적으로 한 번 더 하고 싶은 경험’의 검증으로 전환한다.

사용자는 현재 서비스가 크게 재미없다고 평가했다. 이는 직접 받은 피드백이다. 아래 원인 분석과 해결 방향은 제품 가설이며 방문 분석이나 대표성 있는 사용자 조사 결과는 아니다.

## 현재 구현으로 확인되는 문제
| 문제 | 근거 | 영향 |
|---|---|---|
| 시작이 느림 | 첫 탭이 읽기·실천·기록 중심이고 게임은 별도 탭 | 재미를 원하는 사람에게 먼저 읽고 체크하라는 인상 |
| 퀴즈에 발견이 적음 | 월 10만 원 × 12개월, 명백한 생활 습관 정답 등 | 고민·추측·반전의 여지가 작음 |
| 게임 변화가 약함 | 무작위 7×7 보드, 20회 이동, 점수 중심. 특수 조각·스테이지·장애물 없음 | 판마다 다른 목표나 전략을 기대하기 어려움 |
| 콘텐츠 새로움 부족 | 직접 쓴 14일 콘텐츠 반복, 외부 RSS 제목·링크 | 내일 여기에서만 얻을 경험이 약함 |
| 수집 보상이 약함 | 완료 표시와 7일 정원 | 체크 자체는 플레이의 즐거움을 대체하지 못함 |
| 사회적 동기가 없음 | 게시판은 localStorage 체험용 | 다른 사람의 반응이 생기지 않음 |
| 명확한 타깃 행동이 없음 | 계산기·일기·학습·소식·게임 모두 같은 중요도 | 첫 방문에 무엇을 하면 좋은지 초점 분산 |

차분한 초록 디자인 자체가 실패 원인이라고 단정할 근거는 없다. 다만 현재 텍스트·폼 비중이 놀이 중심 목표와 맞지 않는다. 미세한 색 변경이나 배지 추가는 우선순위가 낮다.

## 참고 서비스와 근거
확인은 공개 문서와 검색 가능한 페이지를 기준으로 했다. 직접 가입·플레이한 사용성 조사로 표현하지 않는다. 트래픽, 월간 사용자, 플레이 횟수는 서로 다른 지표이며 단순 비교 순위로 만들지 않는다. 높은 이용 규모가 특정 UI의 성공 원인을 입증하지는 않는다.

1. [Poki](https://poki.com/): 공식 페이지는 월 1억 명 이상의 플레이어와 설치 없이 즉시 플레이를 안내한다. 첫 페이지부터 게임을 고르는 구조다. 적용할 것은 즉시 시작과 간단한 조작이며 방대한 게임 수를 모방하는 것은 현재 팀 규모에 맞지 않는다.
2. [NYT Games 공식 안내](https://thenewyorktimeshelpcenter.helpjuice.com/360052273251-The-New-York-Times-Games-app): 일일 게임 기록·연속 기록·친구별 리더보드를 제공한다. [AP 보도](https://apnews.com/article/4ab76097d6155a022f089d03e94807c3)는 2025년 게임 전체 플레이가 112억 회 이상이라고 전한다. 적용할 것은 자체적으로 재미있는 일일 문제, 결과 공유, 이후 기록이다. 문제·문구·그래픽은 복제하지 않는다.
3. [네이버웹툰 업데이트 안내](https://help.naver.com/service/5635/contents/18614?lang=ko&osType=COMMONOS): 요일별 회차 공개 일정이 있다. [WEBTOON 공시](https://ir.webtoon.com/node/8081/html)는 짧은 회차의 정기 연재, 작품과 창작자에 대한 유대, 회차 말 댓글 참여를 설명한다. 적용할 것은 이어지는 이야기와 다음 편 기대다. 공개 규모는 WEBTOON 그룹 지표와 네이버웹툰 단독 지표를 구분해야 한다.
4. [Duolingo 공식 실적 발표](https://investors.duolingo.com/news-releases/news-release-details/duolingo-reports-fourth-quarter-and-full-year-2025-results): 2025년 말 일간 활성 사용자 5천만 명을 넘겼다고 발표했다. 다만 배우고 싶다는 본래 동기가 있는 학습 서비스다. 출석과 포인트만 가져와도 엔터테인먼트 재미가 생긴다고 해석하지 않는다.

## 새 제품 방향 후보
| 방향 | 핵심 재미 | 현재 구현 난이도 | 운영 부담 | 판단 |
|---|---|---|---|---|
| 오늘의 3분 퍼즐 | 선택·발견·성공·재도전 | 중간, 정적 구현 가능 | 일일 퍼즐 품질 검수 | 첫 검증 추천 |
| 직장인 선택형 이야기 | 공감·반전·다른 결말 | 중간, 정적 구현 가능 | 원고·분기·삽화 제작 | 별도 소규모 시안으로 비교 |
| 재미있는 정보 모음 | 놀라움·발견 | 낮음~중간 | 매일 큐레이션·출처 관리 | 보조 콘텐츠 |
| 실제 커뮤니티 | 공감·반응·참여 | 인증·DB·운영 필요 | 초기 글 공급·신고 대응 | 초기 주력으로는 보류 |

추천 포지셔닝은 ‘출퇴근길 3분 놀이터’. FIRE는 관심 주제 중 하나로 남기고 모든 재미를 금융 교육으로 묶지 않는다. 새 방향은 검증할 제안이며 기존 브랜드와 기능을 아직 변경하지 않았다.

## 첫 개선 범위 제안
### 1. 첫 화면
설명·출석·일기보다 ‘오늘의 3분 퍼즐 — 바로 시작’을 먼저 배치한다. 그 아래 이어하기, 새 회차 또는 짧은 발견 하나만 둔다. 기록은 결과 화면 또는 보관함으로 이동한다. 계산기는 도구로 유지한다.

### 2. 현재 3매치 개선
- 점수 모으기 대신 ‘15번 안에 특정 조각 수집’ 같은 구체 목표를 둔다.
- 4개/5개 매치의 특수 조각, 제한된 장애물 등으로 선택의 깊이를 더한다. 규칙은 첫 시연에서 짧게 설명한다.
- 조각 이동·연쇄·목표 달성 피드백을 명확하게 한다. 소리는 선택 사항이고 줄인 모션 환경을 존중한다.
- 짧은 스테이지 3~5개로 재미부터 검증한다. 매일 자동 생성은 풀 수 있는 문제인지 검수할 수 있을 때 확대한다.
- 일일 모드는 날짜별 동일한 문제와 규칙으로 제공한다. 자유 연습과 일일 기록을 구분하고, 새로고침으로 결과를 무제한 갱신하는 정책을 명시한다.
- 결과는 스포일러 없는 텍스트 공유와 같은 퍼즐 링크로 전달할 수 있다. 서버 없이도 가능하지만 공용 순위나 참여자 비율은 만들지 않는다.

### 3. 선택형 이야기 비교 시안
첫 소재 예: ‘퇴사까지 30일 — 오늘 갑자기 들어온 제안’. 60~90초 안에 상황→선택 두 번→결말→다른 선택 보기로 끝낸다. 수익률 맞히기가 아니라 생활의 딜레마와 유머를 중심으로 한다. 작은 완결과 다음 편의 궁금증이 모두 있어야 한다. 신규 원고를 만들 인력이 없으면 매일 연재를 약속하지 않는다.

### 4. 정보 콘텐츠
일반적인 절약 조언과 기사 목록은 보조로 낮춘다. 한 장의 독특한 발견을 ‘흥미로운 질문→사실→왜 놀라운가→출처’로 편집한다. 예시: 생활 속 비용 비교, 착시·관찰 퀴즈, 공공데이터 기반 의외의 사실. 사실 확인과 재사용 권한이 확보된 자료만 쓴다. 개인화·AI 무한 생성은 첫 실험에 넣지 않는다.

## 역할별 다음 과제
- 기획: 동일한 대상에게 보여줄 퍼즐 시안과 이야기 시안의 1회 경험·완료 기준 작성.
- 디자인: 첫 10초에 주 행동을 찾을 수 있는 모바일 화면, 조작 피드백과 결과 화면 설계.
- 개발: 기존 계산기·기록을 보존하면서 3~5개 퍼즐 시안 또는 1편 이야기 시안을 독립 경로로 구현. 신규 DB 없이 시작 가능.
- QA: 모바일 조작, 풀 수 있는 퍼즐, 분기 누락, 중단·복귀, 저장 정책 검증.
- 콘텐츠: 실제 재미있는 문제·원고를 사람이 고르고 검수. 단순한 일정 변경을 새 콘텐츠라고 표현하지 않기.
- PM: 작은 체험 결과를 보고 하나를 주력으로 선택. 두 가지를 모두 큰 제품으로 확장하지 않기.

## 검증 방법
동의한 소수의 출퇴근 사용자에게 설명을 최소화해 두 시안을 보여준다. 초기 5명 테스트는 문제를 찾는 정성 조사이며 시장성을 증명하는 표본으로 보지 않는다.
- 어디를 먼저 누르는가, 규칙을 혼자 이해하는가?
- 한 판/한 편 뒤 부탁하지 않아도 다시 하는가?
- 무엇이 재미있었고 어떤 순간에 지루해졌는가?
- 다음날 무엇이 새로 나오면 다시 열겠는가?
- 실제로 다음날 다시 열었는지, 그 이유는 무엇인가?

첫 판단 기준의 예: 5명 중 3명이 자발적으로 재도전하면 후속 실험 가치가 있다고 판단한다. 이는 업계 기준이 아닌 내부 임시 기준이다. 자동 분석을 붙이려면 수집 범위와 동의를 별도 설계하며, 현 단계에서는 관찰·간단한 후기만으로 시작할 수 있다.

방문 수는 유입 규모, 재방문은 유지, 수익은 전환 문제다. 한 가지를 개선했다고 세 가지 모두 좋아졌다고 보고하지 않는다. 재미가 확인되기 전 광고·결제·실제 커뮤니티를 확대하지 않는다.
